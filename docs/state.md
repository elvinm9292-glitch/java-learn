## Срочно, вне учёбы

- **Токен Vault в `application.properties`** — прописан как значение
  по умолчанию и уже отправлен на GitHub (`origin/main`). Отозвать токен
  через того, кто отвечает за Vault; в файле оставить `${VAULT_TOKEN}`
  без значения по умолчанию. Удаление строки из файла не помогает —
  токен остаётся в истории git.

## Что есть в коде

- **`account/`** — открыть, найти по id, список, пополнить, снять,
  заблокировать. Логика денег внутри `Account` (`deposit`, `withdraw`,
  `block`), публичного `setBalance()` нет, конструктор баланс не принимает.
- **`@Version`** на `Account` + миграция `V2__add_version_to_account.sql`.
- **Flyway подключён**, `ddl-auto=validate`, `baseline-on-migrate=true`.
- **`card/`** — выпуск карты по IBAN, блокировка. Номер — случайные цифры,
  CVV хранится как есть (осознанное решение, см. `decisions.md`).
- **`transfer/`** — `TransferService.transfer(fromIban, toIban, amount)`
  в одной транзакции. Контроллера нет.
- **`common/validation`** — `@ValidIban`, проверка формата AZ IBAN.
- `GlobalExceptionHandler` в `account/` отдаёт честный 404.

## Мешает запуску

- ~~Два класса `GlobalExceptionHandler`~~ — 2026-11-01 подтвердилось
  логом (`ConflictingBeanDefinitionException`), пустой обработчик
  из `card/` удалён. Осталось: перенести обработчик и `ErrorResponse`
  в `common/`, удалить второй `ErrorResponse` из `card/dto`.
- Нет миграции `V1` со схемой. Работает только на базе, где таблицы уже
  есть. На пустой базе `V2` упадёт: таблицы `account` нет.

## Расходится с принятыми решениями

- IBAN присылает клиент (`OpenAccountRequest.iban`), а в `decisions.md`
  решено, что номер выдаёт банк из последовательности.

## Открытые хвосты

Деньги:
- Пополнение (`POST /{id}/deposit`) создаёт деньги из ничего: баланс
  растёт, записи об операции нет. Перевод — то же самое. Нет журнала
  операций — нечем сверяться.
- Два перевода навстречу друг другу (A→B и B→A) одновременно —
  не разобрано. `@Version` бросит исключение, обработчика на него нет → 500.

Код:
- У `deposit` в контроллере нет `@Valid`, у `withdraw` есть.
- `@Positive(message = "aaa")` в `AmountRequest`.
- `DataIntegrityViolationException` всегда отвечает «DUPLICATE_IBAN»,
  даже если дубликат — номер карты.
- Два `ErrorResponse` (в `account/dto` и `card/dto`) — место в `common/`.
- Сообщения исключений частью по-русски, частью по-английски.
- Пополнение и снятие — по `id`, перевод и выпуск карты — по IBAN.
- `getAll()` без пагинации.
- `existsByNumber`, `findByStatus`, `hasCardWithStatus`, `findByIdWithCards`
  объявлены, но не вызываются.
- Пакет `java_learning/` из первого коммита — со своим `@SpringBootApplication`.
  Удалить.
- Toolchain Java 17, в `CLAUDE.md` — 23. Привести к одному.
- Нет индекса на `cards.account_id`, нет README, нет тестов.
- Всё после первого коммита (31 файл) не закоммичено.

**1.1 (сумма `0.005`) — сделано 2026-11-01.** Решено: лишние знаки

в `Account` сообщения про статус и остаток ещё по-русски.
