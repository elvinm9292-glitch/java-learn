# Коллекции — шпаргалка

Скорость в скобках — как её называют на собеседовании:
**O(1)** — мгновенно, не зависит от размера; **O(log n)** — ~25 шагов на 20 млн;
**O(n)** — перебор всех.

## Основные

| Структура | Что делает | Быстро | Медленно | Когда в банке |
|---|---|---|---|---|
| `ArrayList` | Список по порядку, ячейки подряд | по номеру, в конец — O(1) | вставка/удаление в начале, `contains` — O(n) | 90% случаев: результат из репозитория, список карт клиента |
| `HashMap` | Ключ → значение, ящики по `hashCode` | `get`, `put`, `containsKey` — O(1) | порядка нет | Найти счёт по IBAN, посчитать операции по счёту |
| `HashSet` | Только ключи, «есть или нет» | `add`, `contains` — O(1) | порядка нет | Убрать дубли из файла платежей, «кому уже отправили SMS» |
| `TreeMap` | Ключ → значение, ключи всегда отсортированы | первый, последний, диапазон «от и до» — O(log n) | точный поиск чуть медленнее `HashMap` | Итоги по дням за период, отчёты по датам |
| `ArrayDeque` | Очередь или стек, кольцо в массиве | с обоих концов — O(1) | по номеру нельзя | Очередь платежей на обработку |
| `PriorityQueue` | Первым выходит самый важный | `poll`, `offer` — O(log n), `peek` — O(1) | перебор идёт не по порядку | Срочные платежи вперёд обычных |

## Сверх плана — спрашивают часто

| Структура | Что делает | Когда |
|---|---|---|
| `LinkedHashMap` | `HashMap`, который помнит порядок добавления | Нужен порядок «как пришло» и быстрый поиск |
| `TreeSet` | `HashSet` с сортировкой | Уникальные значения по порядку |
| `ConcurrentHashMap` | `HashMap`, с которым безопасно работать из многих потоков | Общий кеш в singleton-бине Spring (тема «многопоточность») |
| `LinkedList` | Цепочка, каждый помнит соседей | Почти никогда: тяжелее и медленнее на практике |

## Фразы уровня senior

- «По умолчанию `ArrayList`. Для очереди — `ArrayDeque`, `LinkedList` почти не оправдан: накладные расходы на узлы и промахи кеша процессора».
- «`contains` в цикле по списку — это O(n²). Меняю на `HashSet` — становится O(n)».
- «Переопределил `equals` — переопределяю `hashCode` по тем же неизменяемым полям. Иначе равные объекты попадут в разные корзины».
- «Для сущностей JPA `equals`/`hashCode` — по бизнес-ключу, не по `id`: `id` появляется только после сохранения».
- «`HashMap` при заполнении на 75% удваивает корзины и перекладывает всё. Знаю размер заранее — задаю начальную ёмкость».
- «Сортировку и группировку больших данных отдаю базе: `ORDER BY`, `GROUP BY`. Коллекции — для того, что уже в памяти».
- «`HashMap` не потокобезопасен. Из нескольких потоков — `ConcurrentHashMap`».
- «Одинаковый приоритет в `PriorityQueue` не гарантирует порядок прихода — добавляю `thenComparing`».
